# Site security review — 2026-09-20

Reviewed Worker routes, model calls, session storage, browser assets, Cloudflare verification, and consented PostHog capture. Claude Fable 5.1 reviewed this patch twice through the user-requested CLI. The reviews found a broken PostHog routing token, strict control-name matching, shared challenge cancellation, prompt inflation from duplicate controls, and redaction gaps; these were corrected and covered by tests. This is a source and behavior review, not a penetration test or an audit of Cloudflare account permissions.

1. **Credentials and isolation.** Gateway credentials stay in Worker bindings. Gitleaks found no secrets in the working tree, generated assets, or scanned Git history. The `__Host-waymode_session` cookie is HttpOnly, Secure, SameSite=Strict, host-only, and valid for one hour. A derived trace label cannot act as that cookie. Tests cover visitor state, action ownership, trace isolation, and old-cookie rejection. Same-origin checks reject cross-site session creation and foreign mutations. Origin checks alone do not authenticate bots. Paid routes now require Cloudflare Turnstile verification: success, hostname, action, and a session nonce must match. Grants expire after 15 minutes and bind to the session and network quota identity. The model reservation path checks the grant again. Failed checks cannot reserve a model call. Tests mock the Siteverify response to exercise rejection and expiry; real browser verification is a separate release check.

2. **Abuse and cost bounds.** The Worker rejects large bodies and cancels stalled reads after ten seconds. Cloudflare edge rate limits run before shared storage; persistent Durable Object quotas remain authoritative. IPv6 addresses share a /64 bucket. Stored network identifiers use HMAC with a random daily secret. Expiry checks, periodic pruning, trace retention limits, stream caps, and slow-reader cancellation bound storage and memory. At most four model calls run together. Model limits are 12/network/minute, 60/site/minute, 150/site/hour, 100/network/day, and 60/session. The shared daily cap is temporarily 1,200 until September 23, 2026 at 00:00 UTC, then 600. Preview model calls remain disabled. Calls, including failed attempts and the single retry for a gateway internal error, consume reservations; these limits are not a dollar budget. The decision endpoint removes unknown controls, rejects an entirely unknown catalog, bounds repeated templates and total catalog size, and rebuilds model input from generated site metadata, the server-owned product contract, and saved state. Arbitrary client descriptions, schemas, context, IDs, and history details are not forwarded. Browser-only state is limited to enumerated analytics preferences and boolean menu/install disclosure state; it cannot authorize server mutations. Free-text requests and the bounded editable demo setting remain intentional inputs. Passing a browser check does not prove intent; automated browsers, token farms, and distributed visitors can still exhaust the shared pool. Edge counters are eventually consistent, as described in [Cloudflare's documentation](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

3. **Browser and telemetry boundaries.** Script CSP permits self-hosted assets and Cloudflare Turnstile; Turnstile frames are explicitly allowed. Inline executable scripts and Cloudflare's analytics beacon remain excluded. Google Fonts remains an external font request and is disclosed in the privacy page. SQL uses bound parameters and runtime text uses text nodes. API logs retain route, status, timing, and generated request IDs; model logs retain usage and errors without prompt bodies, raw IPs, or auth cookies. Invocation logging is disabled. Request scopes separate concurrent model logs. No uptime alerts, log export, or provider dollar budget is configured in this change.

4. **Consented analytics.** PostHog `1.434.2` is connected to the Waymode US project (619493), with 30-day replay retention, heatmaps, performance capture, and console capture enabled. The SDK loads only after visitor opt-in; GPC and Do Not Track override it. Autocapture handles clicks and navigation; ordinary text, inputs, and visible traces are readable in replay after consent. A runtime bridge records submitted and suggested prompts, decisions, outcomes, and stops. Password fields, hidden credentials, network bodies, auth headers, cookies, and security widgets are excluded from replay. Event and console-log hooks redact credential fields and common secret patterns. Arbitrary confidential text cannot be detected reliably. URL queries and fragments are stripped, including URLs in console text; public Google Fonts family/display parameters are retained for replay styling. Withdrawal stops future capture but does not erase prior records. Browser blockers, SDK limits, and payload bounds prevent complete capture. Live event queries confirmed page views, autocapture, web vitals, dead clicks, and Waymode activity. Replay remains blocked: the project API reports recording enabled, but PostHog’s public browser configuration still returns `sessionRecording: false`; listing recordings returned none after reapplying the setting. Console capture is enabled in the SDK and project; replay/console ingestion is not yet proven.

5. **Current evidence.** `npm run verify` passed 157 tests across 37 files, lint, types, formatting, production builds, and release checks. Dependency installation reported zero known vulnerabilities. Gitleaks found no leaks in the working tree and generated assets. The Worker dry run compiled successfully. Local browser checks confirmed the security dialog appears before model work and cancels cleanly. Earlier live checks proved visitor isolation, private-path 404s, and the native Cloudflare rate limit; new live checks confirmed that every paid entry point rejects an unverified session even with a forged same-origin header, invalid Turnstile tokens fail, and a normal browser passes the managed check before invoking Waymode. The live runtime opened analytics preferences, changed the choice, and reopened the menu; saved preference state supports completion checks. A guidance run exposed a gateway internal error at completion. After adding one retry with a fresh quota reservation, the live “Show me how to allow analytics” run finished and the saved choice was `yes`. Repeated gateway failures remain possible. Production workers.dev and preview URLs are disabled. No uptime alerts, provider dollar budget, or log export destination is configured by this patch.
