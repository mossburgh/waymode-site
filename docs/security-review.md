# Site security review — 2026-09-20

Reviewed production revision `64d5beb`, its Worker, built browser assets, and the local navbar runtime prototype. This is a source and behavior review, not an independent penetration test or a review of Cloudflare account permissions.

1. **Credentials and sessions.** `hosted/model.ts` reads the gateway key from Worker bindings; client builds do not import that module. Gitleaks found no secrets in the site's 13 commits or built public assets. The session response did expose the anonymous cookie value inside `traceChannel`. The fix derives the channel with SHA-256, so the browser-readable label cannot serve as a session credential. The cookie remains HttpOnly, Secure, SameSite=Strict, with a one-hour lifetime. Tests check stable channels, distinct visitors, and rejection of a channel used as a cookie.

2. **Request and data boundaries.** The Worker rejects foreign origins and requires a matching Origin for mutations. JSON is capped at 16 KiB and validated. SQL uses bound parameters. Tests cover visitor state, action ownership, and trace isolation. Model responses and chat input reach the DOM through text nodes. Model input contains page observations, not the gateway key. Traces contain the visitor's requests and model output; people should avoid entering secrets. The client keyword filter is not a security boundary.

3. **Transport and lifetime fixes.** Live checks confirmed missing HSTS; static and API responses now set a one-year policy without applying it to other subdomains. Activity streams now clear their timer when a visitor expires, preventing a second close of an already closed stream. A fake-clock test covers that case. The local prototype also rejects unrecognized Host headers before serving files or forwarding requests, closing a DNS-rebinding path into its loopback proxy.

4. **Spending and remaining hardening.** The server reserves at most 600 model calls/site/day, 100/IP/day, and 60/visitor/hour, with at most four active calls site-wide. Limits persist in Durable Object storage. They cap calls, not dollars; anonymous visitors can consume shared allowance. Origin checks are browser protections, not bot authentication. Failed calls can have unknown cost; reported zero does not promise free usage. A gateway budget would add a separate spending limit. The static CSP still permits inline scripts; moving them into files and removing `unsafe-inline` is a useful next hardening step. No injection path was found in the reviewed renderers.

5. **Evidence and limits.** `npm run verify` passed 100 tests plus lint, type checks, format, build, and release checks. `npm audit` reported zero known vulnerabilities. Gitleaks found no secrets in production history/assets or prototype assets. Live checks returned 401 for an unauthenticated app read and 404 for `.env`, `.dev.vars`, Git config, and server source. CodeRabbit was signed out; review used source inspection, scanners, and regression tests. The navbar completed an installation handoff in a real browser; a preceding run hit a gateway error after two actions. These checks do not prove the absence of all vulnerabilities.
